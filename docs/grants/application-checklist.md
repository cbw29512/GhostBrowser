# Ghost Browser Grant Application Checklist

Use this checklist for every grant application to make sure Ghost Browser materials are complete, accurate, and reusable.

---

## Core Project Readiness

- [ ] GitHub repository is public and accessible
- [ ] README is current and clearly explains the project
- [ ] LICENSE file is present
- [ ] ROADMAP.md is present
- [ ] architecture documentation is present
- [ ] grant documents folder is organized
- [ ] screenshots, mockups, or diagrams are available
- [ ] project status is accurately described

---

## Reusable Grant Documents

- [ ] quick pitch is ready
- [ ] 150-word abstract is ready
- [ ] 500-word summary is ready
- [ ] full narrative is ready
- [ ] budget narrative is ready
- [ ] milestones document is ready
- [ ] founder bio is ready
- [ ] why-this-matters statement is ready
- [ ] security model document is ready
- [ ] funder mapping document is ready

---

## Before Applying to a Specific Grant

- [ ] confirm the grant is still open
- [ ] confirm the deadline has not passed
- [ ] confirm Ghost Browser matches the grant mission
- [ ] identify the best positioning angle
- [ ] review eligibility requirements
- [ ] review funding size and allowed uses
- [ ] note required attachments
- [ ] note word or character limits
- [ ] note whether open source is required or preferred
- [ ] note whether a budget is required
- [ ] note whether a timeline is required

---

## Positioning Angle Selection

Choose the best primary angle for the application:

- [ ] open-source security infrastructure
- [ ] privacy-preserving computing
- [ ] ephemeral secure workspace
- [ ] portable secure browser environment
- [ ] cybersecurity learning or lab platform
- [ ] public-interest technology
- [ ] trusted temporary workspace for sensitive tasks

---

## Proposal Customization

- [ ] tailor the first paragraph to the funder
- [ ] tailor the problem statement to the grant theme
- [ ] tailor the impact statement to the funder’s priorities
- [ ] tailor milestones to the requested funding level
- [ ] tailor the budget to the requested amount
- [ ] use the funder’s language where appropriate
- [ ] keep the technical claims realistic
- [ ] keep the long-term vision ambitious but believable

---

## Quality Control

- [ ] check grammar and spelling
- [ ] remove vague or repetitive wording
- [ ] confirm all deadlines and dates
- [ ] confirm all funding numbers
- [ ] confirm all links work
- [ ] confirm GitHub repo reflects the proposal
- [ ] confirm open-source claims match the repo license
- [ ] confirm roadmap matches milestone language
- [ ] confirm no contradictory statements appear across documents

---

## Submission Readiness

- [ ] application form completed
- [ ] required documents attached
- [ ] budget attached if required
- [ ] narrative pasted into correct fields
- [ ] tracker updated before submission
- [ ] final review completed
- [ ] submission confirmation saved
- [ ] follow-up date noted in tracker

---

## Post-Submission

- [ ] update tracker status to submitted
- [ ] save a copy of the submitted text
- [ ] save confirmation email or screenshot
- [ ] log any follow-up requirements
- [ ] note expected response window
- [ ] prepare revisions for reuse in future grants

---

## Notes

This checklist is intended to make Ghost Browser grant applications fast, repeatable, and consistent across multiple funding opportunities.
